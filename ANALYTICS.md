# Аналітика «Прогностика 2027»: як розгорнути

Шлях даних: події з лендингу, бота, оплат і мініапки потрапляють на сервер мініапки (`server/server.js`). Там вони зберігаються в SQLite (`data/analytics.sqlite`). Кожні 30 секунд сервер вивантажує їх у Google Таблицю.

Таблиця: **Прогностика 2027: аналітика** (власниця Марія, Google Drive). Вкладки:

- **Дашборд**: воронки, сегменти, тарифи, місяці, картки, графік по днях, джерела.
- **Люди**: по рядку на людину, із сегментом.
- **Оплати**: по рядку на замовлення.
- **Події**: усі події, лише дописуються.
- **Довідник подій**.

Код подій і сегментів: `server/analytics.js`. Тести: `cd server && node --test`.

---

## 1. Google Таблиця: приймач (один раз, 5 хвилин)

1. Відкрити таблицю → **Розширення → Apps Script**.
2. Замінити вміст `Code.gs` вмістом файлу `google-sheets/Code.gs`. Зберегти.
3. **Налаштування проєкту** (шестерня) → **Властивості скрипту** → додати `SECRET` = довгий випадковий рядок (наприклад, `openssl rand -hex 32`).
4. **Розгорнути → Нове розгортання → Вебзастосунок**:
   - виконувати від імені: **Я**;
   - доступ: **Усі**. Без входу, захист — секрет.
5. Скопіювати адресу `https://script.google.com/macros/s/…/exec`.
6. Перевірка: у редакторі виконати функцію `selfTest`. У вкладці «Події» з'явиться рядок «Тест підключення». Його можна видалити.

Після зміни `Code.gs` потрібно **Розгорнути → Керування розгортаннями → Редагувати → Нова версія**, інакше працює стара.

## 2. Змінні сервера мініапки

| Змінна | Значення |
|---|---|
| `BOT_TOKEN` | токен бота. Без нього Telegram ID із мініапки не приймається: сервер перевіряє підпис initData |
| `ANALYTICS_SERVER_KEY` | довгий випадковий ключ для подій бота й оплат |
| `SHEETS_WEBHOOK_URL` | адреса `…/exec` з кроку 1.5 |
| `SHEETS_SECRET` | той самий рядок, що `SECRET` у скрипті |
| `LANDING_ORIGINS` | `https://prognostika.alinagricaenko.com.ua` (через кому, якщо доменів кілька) |
| `TRUST_PROXY` | `1`, якщо сервер стоїть за nginx/Cloudflare |
| `ANALYTICS_DB` | за потреби інший шлях до бази. Папка `data/` не потрапляє в git |

Базу `data/analytics.sqlite` потрібно зберігати між деплоями (volume) і робити її резервні копії. Таблиця лише її відображає.

## 3. Мініапка

Уже підключено в `index.html` (функція `track`). Події надсилаються пачками на `POST /api/event` разом із `Telegram.WebApp.initData`. Telegram ID сервер бере тільки з перевіреного підпису. У статичній версії (GitHub Pages, `PROG_STATIC`) аналітика вимкнена.

## 4. Бот і оплати: що надсилати

Запит:

```
POST https://<сервер мініапки>/api/event/server
Authorization: Bearer <ANALYTICS_SERVER_KEY>
Content-Type: application/json

{ "events": [ { "name": "...", "tg": {id, username, first_name}, "order_id": "...", "visitor_id": "...", "props": {...}, "ts": 1764300000000 } ] }
```

`ts` можна не передавати, тоді береться поточний час. За один запит можна надіслати до 100 подій.

**Вебхук оплати** (сайт / платіжна система):

| Коли | `name` | `props` |
|---|---|---|
| створено замовлення | `payment_created` | `plan` (`monthly` / `annual` / `full` / `vip`), `amount`, `currency`, `provider` |
| оплата пройшла | `payment_success` | те саме |
| оплата не пройшла | `payment_failed` | те саме + `reason` |
| повернення | `payment_refunded` | те саме |

Для подій оплати `order_id` обов'язковий. Якщо вебхук прийде повторно, сума не задвоїться. Якщо відомий `visitor_id` лендингу, його теж варто передати.

**Бот:**

| Коли | `name` | `props` |
|---|---|---|
| `/start` | `bot_start` | `start_param`: те, що після `/start ` |
| натиснута кнопка | `bot_button` | `button` |
| людина написала | `bot_message` | `kind`: `text` / `photo` / … |
| бот надіслав розсилку чи нагадування | `bot_sent` | `kind` |
| заблокував / розблокував (`my_chat_member`) | `bot_blocked` / `bot_unblocked` | без props |
| відкрито доступ після оплати | `access_granted` | `plan` |

У кожній події бота передавайте `tg: {id, username, first_name}` з апдейту Telegram.

## 5. Як лендинг, оплата й бот склеюються в одну людину

- Після оплати сайт веде в бота за посиланням `https://t.me/<бот>?start=o_<order_id>`. Тоді `bot_start` зі `start_param` `o_…` прив'язує оплату й візит лендингу до Telegram ID.
- Кнопка «в бота» без оплати веде на `?start=v_<visitor_id>`.
- Будь-яке інше значення (`?start=insta`) записується як джерело.

Без цього посилання людина, яка оплатила, лишиться в сегменті «Оплатив — не зайшов у бот».

## 6. Лендинг

Лендинг зараз рахує кліки власним лічильником (`landing/track.js`). Щоб лендинг теж потрапляв у таблицю, він має надсилати події на сервер мініапки:

```js
navigator.sendBeacon('https://<сервер мініапки>/api/event', JSON.stringify({
  vid: '<випадковий id з localStorage, A-Z a-z 0-9 _ ->',
  events: [{ n: 'landing_view', p: { utm_source, utm_medium, utm_campaign, utm_content, utm_term, referrer, path }, t: Date.now() }]
}));
```

Події лендингу:

- `landing_view`;
- `tariff_click` з `{plan}`;
- `checkout_start` з `{plan}`;
- `bot_link_click`;
- `landing_click` з `{target}`.

Той самий `vid` треба передати платіжній системі в метадані замовлення (повернеться у вебхуку як `visitor_id`) і додати в посилання на бота (`start=v_<vid>`).

## 7. Сегменти (колонка «Сегмент» у «Люди»)

Від оплачених до неоплачених:

- Оплатив — не зайшов у бот
- Оплатив — у боті, не відкрив застосунок
- Оплатив — відкрив, не ввів дату
- Оплатив — ввів дату, не читав
- Оплатив — користується
- Повернув кошти
- Не вдалася оплата
- Почав оплату — не завершив
- Відкрив застосунок — не купив
- У боті — не відкрив застосунок
- Обрав тариф — не оплатив
- Лише лендинг

## 8. Персональні дані

Зберігаються Telegram ID, username, ім'я, рік народження, а також дії в застосунку. Це треба згадати в політиці конфіденційності. Доступ до таблиці надавайте лише тим, кому він потрібен.
